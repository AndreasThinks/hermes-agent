# Retained automatic reply audio

Automatic gateway speech is now retained outside model context and indexed by the exact persisted assistant row. The runner and base adapter store actual successful synthesis output before transport cleanup; completed streaming TTS stores the provider's actual PCM as WAV. This does not enable voice, alter voice settings or synthesize a second copy. Telegram still receives its text and voice normally, including text fallback when automatic voice delivery raises.

`GET /api/sessions/{session_id}/messages` adds `audio_attachments` to each returned row. `include_audio=true` also returns `audio_messages`, the retained owning rows outside the transcript page, including the existing compression-resume lineage. Ownership stays on the original row and session. Each attachment has `id`, `mime_type`, zero-based `part`, `created_at` (monotonic discovery time) and `expires_at`. Download with the normal authenticated dashboard API at `GET /api/reply-audio/{id}`; optional profile routing matches the session routes. IDs cannot select arbitrary filesystem paths. Expired, invalid and symlinked files are unavailable.

The existing SessionDB schema gains `reply_audio`; no transcript content or model/tool context changes. The finalizer provides `final_message_id` from the persisted turn-owned object (including the alternate projected runtime), and gateway receipts carry the database identity across profile teardown. Missing durable receipts fail closed: no “latest message” inference. Streaming bytes may arrive before the final row; only a completed stream with a final receipt is published. Failed/partial synthesis is not advertised as complete audio. Delivery failure does not erase successful synthesis already retained.

Storage is profile-local beside `state.db` in `reply-audio/`, seven days of availability, at most 256 MiB and 1,024 files, 50 MiB/file and 32 parts/reply. Whole replies are evicted together. Cleanup runs on attachment writes and the gateway's hourly live-profile housekeeping. A stopped process cannot delete expired bytes; API expiry still denies them on the next request. Deterministic identities and first-committed-set semantics make repeated publication idempotent. Unrelated source/cache files are never retention targets. Existing MEDIA tool attachments keep their existing retrieval behavior.

Attachment publication advances session activity, including the currently surfaced resume tip after compression, without modifying reply timestamps. Clients must use attachment discovery time for late audio and query the supplemental rows when their normal transcript page no longer contains the answer. Files are local retained media, not a backup/export guarantee. Restart retains completed publications; a process killed before publication can lose its temporary synthesis/PCM. It must never invent a replacement or associate it with another turn.

Validation uses temporary SQLite/files and fixture synthesis/transport, plus authenticated in-process HTTP. No paid TTS provider or real messaging transport is needed. See the parent workspace's PORT-REPORT.md for port validation and deployment boundaries.
